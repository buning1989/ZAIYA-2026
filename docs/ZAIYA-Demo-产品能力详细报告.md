## 一、落地页（Landing Page）

### 1.1 模块定位

落地页是官网性质的介绍页面，用户在访问网站时首先看到的内容。入口为浏览器直接访问 URL。页面为纵向滚动式单页，自上而下展示产品的品牌叙事、功能介绍、设计理念、团队信息。

落地页顶部导航栏（Nav）包含 "体验 Demo" 按钮，点击后进入 Demo 体验系统。

### 1.2 完整交互流程

1. 用户访问页面，首先看到 Nav 导航栏（固定在顶部）和 Hero 首屏。
2. 向下滚动，依次经过 ProblemSolution（问题与方案）、ClinicalFramework（临床框架）、CharacterDesign（角色设计）、Team（团队）、Vision（愿景）。
3. 页面底部为 Footer（页脚）。
4. 用户点击 Nav 或 Hero 中的 "体验 Demo" 按钮，页面进入 Demo 体验系统（DemoExperience 组件以全屏覆盖层形式渲染，原落地页内容被 aria-hidden 隐藏）。
5. 在 Demo 体验中点击关闭，回到落地页。

### 1.3 底层逻辑规则

- 落地页与 Demo 体验系统通过 `App.tsx` 中的 `demoOpen` 状态切换。`demoOpen` 为 true 时，原落地页内容设置 `aria-hidden` 但保持挂载，DemoExperience 以覆盖层形式渲染在上方。
- URL 参数 `?mode=guided` 或 `?mode=free` 可在初始加载时直接进入 Demo 对应模式。退出 Demo 时清除该 URL 参数。
- 落地页本身为纯展示页，不涉及用户数据输入或状态管理。

### 1.4 状态与边界情况

- 首次访问：完整展示所有落地页区块。
- URL 直接带 mode 参数访问：跳过落地页，直接进入 Demo 体验。
- 退出 Demo：回到落地页，URL 参数被清除，页面停留在退出前滚动位置（因为落地页 DOM 一直保持挂载）。

### 1.5 文案与措辞

（落地页各区块的具体文案暂未在本次报告中逐项摘录，因落地页为营销展示层，内容策划团队已有完整文案。）

### 1.6 视觉/交互细节

- 落地页为纵向滚动单页，背景白色。
- Nav 固定在页面顶部，内容区在其下方。
- Demo 体验以全屏覆盖层形式出现，带有入场/退场动画。

### 1.7 模块间关联

- Nav 和 Hero 中的 "体验 Demo" 按钮是进入 Demo 体验系统的入口。
- 落地页不产生数据，不被其他模块引用。

## 二、Demo 体验系统

### 2.1 模块定位

Demo 体验系统是用户在官网上可以直接交互体验产品核心功能的入口。提供两种模式：
- **引导式演示（Guided）**：按预设脚本逐步展示产品功能，用户无法自由操作，只能按步骤前进/后退。
- **自由体验（Free）**：用户可以在手机框架内自由操作产品所有功能，仅受 Demo 阶段未开放功能的限制。

入口为落地页的 "体验 Demo" 按钮，或直接通过 URL 参数 `?mode=guided` 或 `?mode=free` 访问。

### 2.2 完整交互流程

#### 引导式演示（Guided Mode）

1. 用户点击 "体验 Demo"，DemoExperience 全屏覆盖层打开。
2. 如果用户未选择模式，先看到 DemoModeSelector（模式选择页），提供两个选项：
   - "引导式演示"：按预设脚本逐步展示
   - "自由体验"：在手机框架内自由操作
3. 选择 "引导式演示" 后，进入 XiaochenCaseIntro（小晨案例介绍页），展示案例背景。
4. 案例介绍后，进入手机框架（DemoPhoneFrame），内部为 UnifiedDemoStage，展示 App 主界面。
5. 左侧或底部出现 GuidedStoryPanel（故事面板），显示当前步骤的文字说明。
6. 底部有 GuidedDemoControls（导航控件），用户可以：
   - 点击 "下一步" 前进到下一个演示步骤
   - 点击 "上一步" 回退到上一个步骤
   - 通过 GuidedModeSwitch 切换到自由体验模式
7. 演示步骤按预设脚本推进，包括：
   - 首页场景展示（不同时间段在在动画）
   - 对话模式演示（展示 mock 对话）
   - 记一下记录流程演示（展示记录完成态）
   - 夸夸自己演示（展示卡片）
   - 回头看看演示（展示数据回顾）
   - 帮我整理演示（展示沟通材料）
   - 咨询准备页（ConsultationPrepPage）
   - 两周总结过渡页（TwoWeekTransition）
   - 结论总结页（ConclusionSummaryPage）
8. 用户可随时点击关闭按钮退出 Demo。

#### 自由体验（Free Mode）

1. 选择 "自由体验" 后，进入手机框架（DemoPhoneFrame），内部为 AppMainSurface（variant="immersive", interactive=true）。
2. 用户可在手机框架内自由操作，包括：
   - 首页四角图标交互
   - 点击菜单进入更多页
   - 进入各项记录流程
   - 使用对话模式
   - 使用缓解模式（仅呼吸法开放）
   - 使用轻社交模式
3. 手机框架右上角有关闭按钮，点击退出 Demo。
4. 自由体验模式下，部分功能标识为 "暂未开放"（如我的能量、部分缓解能力项）。

### 2.3 底层逻辑规则

#### Demo 模式管理

- `useDemoMode` hook 管理全局演示状态，包括当前步骤、故事面板内容、手机屏幕内模式等。
- `AppMainSurfaceDemoState` 类型定义演示时可注入的外部状态覆盖：
  - `surfaceMode`：覆盖手机屏幕内模式（home/dialog/record/praise/lookback/organize）
  - `now`：固定时间（用于演示特定时间段场景）
  - `bubbleCopy`：覆盖首页气泡文案
  - `dialogItems`：注入对话脚本
  - `socialScene`：控制轻社交场景
  - `recordPreset` / `praiseDemo` / `lookbackDemo` / `organizeDemo`：控制各功能模块的预览态

#### 演示模式下的行为限制

- 演示模式下（`demoEnabled === true`）：
  - 不触发能量奖励（避免评委误触导致脚本偏移）
  - 轻社交结束不触发能量变更
  - 对话模式注入固定脚本时隐藏输入区
  - 系统时间不刷新，使用固定时间
  - 右滑返回手势被禁用（`enableDragExit={!demoEnabled}`）

#### 场景脚本

- 脚本定义在 `src/components/demo/scenarios/` 目录下，包括：
  - `xiaochenDay1.ts`：小晨第一天记录
  - `xiaochenDay2.ts`：小晨第二天记录
  - `xiaochenDay2Records.ts`：第二天记录详情
  - `consultationPrep.ts`：咨询准备
  - `conclusionSummary.ts`：结论总结
  - `xiaochenTwoWeekSummary.ts`：两周总结
- 每个脚本定义了步骤序列，每步包含：故事面板文案、手机屏幕内模式、注入的数据。

### 2.4 状态与边界情况

- 首次访问 Demo：显示模式选择页。
- 直接通过 URL 参数访问：跳过模式选择，直接进入对应模式。
- 演示模式下：用户无法在手机框架内自由操作，所有交互由脚本控制。
- 切换模式：通过 GuidedModeSwitch 可在引导式与自由体验之间切换，切换时保留当前上下文。
- 关闭 Demo：无论当前处于哪个步骤，关闭后回到落地页，URL 参数被清除。

#### 模式选择页

#### 引导式演示控件

- 切换按钮文案：（待补充）

#### 故事面板

### 2.6 视觉/交互细节

- DemoExperience 为全屏覆盖层，覆盖在落地页之上。
- 手机框架（DemoPhoneFrame）模拟真实手机外观，包含圆角边框、顶部状态栏等。
- 引导式演示中，故事面板位于手机框架左侧或底部，文字说明当前步骤。

### 2.7 模块间关联

- 自由体验模式直接复用 AppMainSurface 的完整交互逻辑。

## 三、App 主界面（AppMainSurface）

### 3.1 模块定位

App 主界面是产品核心交互界面，模拟手机 App 的主屏幕。在 Demo 中，它有两种使用方式：
- **Hero 预览态**（variant="hero"）：落地页 Hero 区块中的静态预览，不可交互，仅做视觉展示。
- **沉浸式体验态**（variant="immersive", interactive=true）：Demo 自由体验和引导式演示中的可交互版本。

App 主界面采用"首页内模式切换"架构：所有子功能（对话、缓解、轻社交、记录、更多菜单等）均在首页内以覆盖层/动画切换形式展开，不跳转独立页面。

### 3.2 完整交互流程

#### 首页（home 模式）

进入首页后，用户看到：

1. **顶部**：iOS 风格状态栏（时间 9:41 / 信号 / Wi-Fi / 电池）。在 immersive 模式下，状态栏时间固定为 "9:41"（装饰性 phone chrome），实际时间信息由 HomeTimeAnchor 承载。
2. **中央偏上**：在在动画角色（ZaizaiHomeScene），根据当前时间段展示不同场景动画。
3. **在在附近**：轻气泡（HomeBubbleCopy），随机展示 3 句文案中的 1 句。
4. **在在动画上方**：时间锚点（HomeTimeAnchor），两行信息——主信息「时段 时间」（如「晚上 22:46」）+ 次信息「日期 · 周几」（如「7月13日 · 周一」）。
5. **四角图标**：
   - 左上：菜单入口（汉堡菜单图标，点击进入更多侧边栏）
   - 右上：默认空置；开启"记一下快捷入口"后显示记录图标
   - 左下：陪做入口（Users 图标，点击进入轻社交场景选择）
   - 右下两个：Wind（缓解压力，点击进入缓解模式选择）+ MessageCircle（AI对话，点击进入对话模式）
6. **首页轻反馈**：当用户从记录流程"先记到这儿"保存后回到首页，在在下方显示浮动文字「已经帮你保存了。」，4 秒后自动消失。位置在 top: 62%。

#### 对话模式（dialog 模式）

1. 用户点击右下角 AI 对话图标，进入对话模式。
2. 在在动画从居中上移到顶部（约 4% 位置），缩小至 0.65 倍。
3. 在在动画切换为 DialogueZaiyaAnimation（对话专用动画，支持 idle/listening/thinking/responding 四种状态）。
4. 下方展开对话内容区（top: 33%，bottom: 92px），显示 mock 历史对话记录。
5. 底部出现输入区：文本输入框 + 语音入口 + 发送/关闭按钮。
   - 输入框为空时，右侧显示关闭按钮（深色圆形 + 白色 X），点击退出对话回首页。
   - 输入框有内容时，右侧显示发送按钮（accent 圆形 + 白色箭头），点击发送。
   - 发送后，输入框清空，按钮切换回关闭态。
6. 用户发送消息后，系统模拟回复（300-600ms 延迟），回复内容基于关键词匹配（如"起不来"、"不想出门"等），否则返回通用回复。
7. 对话历史中，时间标记以半透明胶囊形式居中显示（如"今天 14:30"、"昨天 21:30"）。
8. 用户消息靠右显示（浅 accent 背景），在在消息靠左显示（浅灰背景）。
9. 对话内容区可滚动，自动滚到底部。
10. 点击关闭按钮退出对话，回到首页。

#### 缓解模式（reliefSelect → breathing）

1. 用户点击右下角 Wind 图标，进入缓解能力项选择页。
2. 在在动画上移缩小，首页四角图标淡出不可点击。
3. 背景出现浅柔灰色降噪层（opacity 0.5）。
4. 下方（top: 54%）出现 2×2 网格，展示 4 个缓解能力项：
   - 呼吸法（可进入）
   - 五感接地（暂未开放，卡片右上角有"暂未开放"标签，点击无反馈）
   - 正念（暂未开放）
   - 蝴蝶拍（暂未开放）
5. 底部中央有收起按钮，点击回到首页。
6. 用户点击"呼吸法"后，进入 BreathingFlow（呼吸法全屏覆盖层）。
7. 呼吸法流程：选择呼吸方法 → 引导练习 → 完成反馈 → 选择回到缓解选择页或回首页。
8. 右上角显示能量入口（EnergyBadge）。

#### 轻社交模式（socialSelect → socialFlow）

1. 用户点击左下角 Users 图标，进入轻社交场景选择页。
2. 在在动画上移缩小，保留气泡，四角图标淡出。
3. 下方出现轻社交场景卡片（2×2 网格），包括：
   - 一起发呆（可进入）
   - 一起吃饭（可进入）
   - 其余标记"暂未开放"
4. 用户选择场景后，进入 socialFlow（全屏覆盖层，在在退出）。
5. 一起发呆（DazeFlow）：用户长按结束 → 获得 +3 能量 → 回到场景选择页。
6. 一起吃饭（EatFlow）：用户完成 → 获得 +3 能量 → 回到场景选择页。
7. 右上角显示能量入口，能量获得时触发 toast 动画（粒子飞向能量入口）。
8. 退出按钮回到场景选择页（非首页）。

#### 更多菜单（more 模式）

1. 用户点击左上角菜单图标，左侧滑入更多侧边栏。
2. 侧边栏宽度 78%，右侧有遮罩层（半透明黑色），点击遮罩关闭。
3. 侧边栏内容分为上下两部分：
   - 上半部分：功能区（记一下 / 回头看看 / 帮我整理 / 夸夸自己 / 我的能量 / 我的隐私）
   - 底部固定：应用级入口（帮助与反馈 / 应用设置）
4. 点击某项进入对应二级页面（moreDetail 模式），从右侧滑入全屏覆盖。
5. "我的能量"点击后显示"Demo 阶段暂未开放"提示。
6. 受保护入口（回头看看 / 帮我整理 / 夸夸自己 / 我的隐私）在应用锁开启且本会话未验证时，先进入验证页。

#### 应用锁验证（verify 模式）

1. 当用户点击受保护入口且应用锁开启且未验证时，进入验证页。
2. 验证页标题："验证后查看"，说明："此内容受应用锁保护。"
3. 按钮："验证并进入"（点击后标记已验证，进入目标页）。
4. 返回按钮回到更多侧边栏。
5. 验证状态仅本会话有效，刷新页面后重置。

### 3.3 底层逻辑规则

#### 时间段判断

- 使用 `getHomeTimePhase(date)` 函数判断当前时段：
  - 06:00-10:00 → morning（早上）
  - 10:00-18:00 → daytime（白天）
  - 18:00-23:30 → evening（晚上）
  - 23:30-06:00 → night（深夜）
- 场景 GIF 素材映射：
  - morning/daytime → `/assets/zaiya/wake-up.gif`
  - evening → `zaizai-reading-night.gif`
  - night → `zaizai-sleeping-breathing.gif`
- `getHomeTimeLabel(date)` 返回时段词：早上（5-9）/ 上午（9-12）/ 下午（12-18）/ 晚上（18-23）/ 夜深了（23-5）

#### 首页模式切换

- 所有模式在 `SurfaceMode` 类型中定义：home / dialog / reliefSelect / breathing / socialSelect / socialFlow / record / praise / lookback / organize / more / moreDetail / verify。
- 模式切换通过 `mode` 状态控制，使用 framer-motion AnimatePresence 实现动画过渡。
- 在在动画位置和缩放随模式变化：
  - home（immersive）：top 39%，scale 1
  - home（hero）：top 34%，scale 1
  - dialog：top 4%，scale 0.65
  - 其他非 home 模式：top 15%，scale 0.65
  - socialFlow / breathing 下在在完全不渲染

#### 对话模式

- 对话消息类型：`DialogItem` = `DialogTimeItem`（时间标记）| `DialogMessageItem`（消息）。
- 时间标记插入规则：当前消息与上一条时间标记不在同一天，或不在同一分钟时，插入新的时间标记。
- 时间格式化规则：
  - 今天 → "今天 HH:MM"
  - 昨天 → "昨天 HH:MM"
  - 更早 → "周X HH:MM"
- 在在动画状态机（优先级从高到低）：
  - thinking（等待回复中）
  - responding（回复刚出现，且输入框为空）
  - listening（输入框聚焦或有内容）
  - idle（默认）
- 回复为本地 mock，不接 LLM/API。关键词匹配逻辑：
  - 匹配"起不来/不想动/没力气/没劲/躺着" → 回复鼓励起床
  - 匹配"不想出门/出门/上学/见人" → 回复建议最小步骤
  - 其他 → 通用回复
- 演示模式下输入对话脚本时，整个输入区隐藏。

#### 能量系统

- 使用 `useEnergy` hook 订阅全局 pub/sub，跨模块同步。
- 能量值存储在 `userProfile` 中。
- 轻社交完成获得能量：一起发呆 +3，一起吃饭 +3。
- toast 动画：粒子从页面中央飞向能量入口，飞行期间冻结展示值，到达后解冻并触发 pulse 动画（420ms）。
- 演示模式下不触发能量奖励。

#### 快捷入口触发逻辑

- `checkShortcutPrompt` 函数判断是否在记录完成页展示"添加快捷入口到首页"提示。
- 四个触发条件（满足任一即触发）：
  1. 连续 3 个自然日内每天至少 1 条完整记录
  2. 过去 7 天内累计 ≥ 5 条完整记录
  3. 同一核心记录类型累计 ≥ 3 次完整记录
  4. 连续 2 次从"更多"进入并完成完整记录
- 排除条件：
  - 已开启快捷入口 → 不提示
  - 7 天内点过"暂不" → 不提示
  - 无完整记录 → 不提示

#### 应用锁

- 应用锁状态存储在 localStorage（key: `zaiya_app_lock`）。
- 受保护入口（4 个）：回头看看 / 帮我整理 / 夸夸自己 / 我的隐私。
- 不保护入口：记一下的新建入口 / 帮助与反馈 / 设置首页 / 隐私条款 / 用户协议。
- sessionVerified 仅本会话有效，刷新页面后重置。

#### 记录历史

- `recordHistory` 追踪每次记录的类型、时间、是否完整、来源。
- 初始含一条 mock 体重历史记录（55.0 KG），用于体重页默认值。
- 睡眠记录：同一天只保留一条，新记录覆盖旧记录。
- 体重记录：保存体重值用于下次默认值。

### 3.4 状态与边界情况

- **首次使用**：首页四角图标均为可交互，右上角无快捷入口（默认关闭）。
- **空对话历史**：对话内容区显示引导文字「在这里说一句话试试。」
- **发送中状态**：在在显示 thinking 动画，对话区底部显示「在在正在听…」气泡。
- **回复到达**：在在切换到 responding 动画（1200ms 后自动回到 idle）。
- **未开放功能**：点击时显示"暂未开放"标签或 toast 提示，不执行任何操作。
- **返回确认**：记录流程中有未保存内容时，返回操作触发确认对话框（底部浮层，三选一：继续记录 / 保存当前内容 / 不保存退出）。
- **已保存后返回**：直接返回，不触发确认。
- **无内容记录返回**：直接返回，不触发确认。

## 四、记录流程（RecordFlow）

### 4.1 模块定位

记录流程（"记一下"）是用户日常记录健康和生活状态的核心入口。用户从更多菜单或首页快捷入口进入。覆盖 6 种记录类型：情绪、服用、饮食、睡眠、活动、体重。每种类型有独立的 Wizard 组件，采用"一次只看一个问题"的单页单项流，不使用长表单。

### 4.2 记录首页（RecordHome）

#### 完整交互流程

1. 用户从更多菜单点击"记一下"进入记录首页。
2. 页面顶部显示标题"记一下"，左侧返回按钮，右上角能量入口（EnergyBadge）。
3. 页面中央展示 6 种记录类型入口（2×3 网格卡片）：
   - 情绪（CloudSun 图标）
   - 服用（Pill 图标）
   - 饮食（Utensils 图标，标注"提醒"标签）
   - 睡眠（Moon 图标，标注"提醒"标签）
   - 活动（Footprints 图标）
   - 体重（Weight 图标）
4. 底部展示最近一条记录摘要（日期 + 文字），格式如「7月4日 情绪偏低，下午有一阵特别闷，与人际有关。」
5. 用户点击任一类型卡片，进入对应 Wizard 流程。
6. 点击返回按钮回到更多侧边栏。

#### 底层逻辑规则

- 6 种记录类型定义在 `recordTypes` 数组中，每种类型包含 id、name、Icon、reminderAllowed（是否允许设置提醒）、hasCompletenessExtras（是否要求补充字段才算完整记录）、mockRecentSummary（最近记录摘要）。
- 情绪、服用、饮食、睡眠、活动、体重均使用独立的 Wizard 组件，不走通用 step 系统。
- 体重记录：页面初始化时读取 recordHistory 中最近一条体重记录值作为默认值（初始 mock 为 55.0 KG）。

#### 文案与措辞

- 页面标题：「记一下」
- 卡片标签：情绪 / 服用 / 饮食 / 睡眠 / 活动 / 体重
- 提醒标签：「提醒」（仅服用和饮食显示）
- 返回按钮 aria-label：「返回更多」

#### 视觉/交互细节

- 类型入口为 2×3 卡片网格，每张卡片包含图标、名称、可能的提醒标签。
- 能量入口在右上角，显示能量数值。

### 4.3 情绪记录（MoodRecordWizard）

#### 完整交互流程

情绪记录采用 5 步逐页流程，另加安全承接页和确认页：

**Step 1：一级情绪状态（轮播卡片）**
1. 页面标题"今天感觉自己怎么样？"，5 张情绪卡片以轮播形式展示：很糟 / 不太好 / 一般 / 还行 / 很好。
2. 当前卡片居中，左右各露出一张侧边卡（scale 0.9，文字隐藏，仅露边缘约 20-30%）。
3. 用户左右滑动或点击侧边卡切换。
4. 用户点击当前卡片选中，选中后卡片短暂弹跳动画（scale 1→1.04→1），右上角出现勾选标记，自动进入 Step 2。

**Step 2：具体感受（多选）**
1. 根据一级情绪极性（negative/neutral/positive）展示不同的二级感受词组。
2. 负向极性展示 4 组词（焦虑/害怕、烦躁/生气/抗拒、难过/委屈/自责、累/提不起劲/麻木/空/想躲起来/说不上来），共约 26 个词。
3. 中性极性展示 1 组词（平静、还可以）。
4. 正向极性展示 2 组词（轻松/安心/开心/满足/有希望/有动力、说不上来）。
5. 用户可多选感受词，以胶囊标签形式展示。
6. 选好后底部出现"下一步"按钮，点击进入 Step 3。

**Step 3：原因（多选）**
1. 根据已选二级词决定三级题干和选项池。
2. 负向统一池含 36 个选项，按 4 个小标题显示：学习/工作、人和关系、身体和日常、心里的感觉。
3. 正向统一池含 16 个选项，平铺展示，不分小标题。
4. 中性极性在三级选项池上与正向同池。
5. 末尾最后一个选项为"说不上来"。
6. 用户多选原因，底部出现"下一步"按钮。点击进入 Step 4。

**Step 4：特殊情况大类（轮播卡片）**
1. 展示 4 个特殊情况大类卡片（轮播，同 Step 1 样式）：吃东西/体重这件事、伤害自己、伤害别人的念头、想结束生命。
2. 每种情况有具体描述。用户可选中其中一个，也可跳过不选。
3. 选中后自动进入 Step 5。

**Step 5：特殊情况细项（多选）**
1. 根据 Step 4 选中的大类显示该大类下属的具体细项。
2. 用户多选后，底部出现"下一步"按钮。
3. 点击后进入确认页。

**安全承接页（条件触发）**
1. 如果用户在 Step 4 选中了"伤害自己"或"想结束生命"，自动进入安全承接页。
2. 页面展示安抚文案，提供两个出口：
   - "去跟 ZAIYA 聊一聊"（预填安全起始文案）
   - "查看紧急联系人"（展开热线号码和 mock 联系人）
3. 用户也可选择"继续记录"回到正常流程。

**确认页**
1. 汇总展示用户所有选择：一级情绪、二级感受、三级原因、特殊情况、补充说明。
2. 用户可点击"修改"按钮回到任一步骤修改。
3. 底部按钮："完成记录"（保存后原地切换 success 态，显示盖章动画）/ "先记到这儿"（保存为 basic 记录，回到首页）。
4. 完成记录后触发能量奖励（+10 能量），显示光反馈动画。

#### 底层逻辑规则

- 一级情绪分值映射极性：1-2 分 → negative / 3 分 → neutral / 4-5 分 → positive。
- 二级感受词按 polarity 分组展示，从 `secondaryMoodGroups` 配置读取。
- 三级选项池收敛为两套统一池：负向统一池（36 项，4 小标题分组）和正向统一池（16 项，平铺）。三级题干由已选二级词决定，但选项池固定。
- 特殊情况大类独立于前三层，不受前面选择影响。
- 安全承接页触发条件：Step 4 选中"伤害自己"（abnormal 标记）或"想结束生命"。

#### 文案与措辞

- Step 1 标题：「今天感觉自己怎么样？」
- 一级情绪标签：很糟 / 不太好 / 一般 / 还行 / 很好
- Step 2 负向标题：「感觉到了哪些？」
- Step 2 正向标题：「具体是哪些感觉？」
- Step 3 负向标题：由已选二级词决定，如「在焦虑/害怕哪些事？」
- Step 3 小标题：学习/工作 / 人和关系 / 身体和日常 / 心里的感觉
- 确认页标题：「记一下」
- 确认页按钮：「完成记录」/「先记到这儿」
- 完成反馈盖章文字：「已记录」
- 安全承接页标题：「这一刻先照顾好自己」
- 安全承接页按钮：「去跟 ZAIYA 聊一聊」/「查看紧急联系人」

#### 视觉/交互细节

- 轮播卡片：当前卡片居中，左右露出侧边卡（scale 0.9，文字隐藏），拖动切换方向。
- 选中反馈：卡片弹跳动画（scale 1→1.04→1，duration 700ms），右上角勾选标记。
- 胶囊标签：灰色背景，多选胶囊数组。
- 完成页：盖章动画叠加在确认页上方。

### 4.4 服用记录（MedicationRecordWizard）

#### 完整交互流程

服用记录采用 3 步分页流程：

**Step 1：服药时段**

**Step 2：起效时间**

#### 文案与措辞

- 选项：早上的药 / 晚上的药
- Step 2 标题：「吃药后大概多久起效？」

### 4.5 饮食记录（MealRecordWizard）

#### 完整交互流程

饮食记录采用 4 步分页流程：

**Step 1：餐次**

3. 底部"下一步"按钮。

**Step 3：吃完感受**

3. 底部"下一步"按钮。

#### 文案与措辞

### 4.6 睡眠记录（SleepRecordWizard）

#### 完整交互流程

睡眠记录采用 7 步分页流程（每步均为范围选项，不使用滚轮或分钟输入）：

**Step 1：整体睡眠感受**
1. 标题"昨晚睡得怎么样？"，3 个选项：好 / 一般 / 不好。
2. 单选，选中后自动进入 Step 2。

**Step 2：具体睡眠感受**
1. 根据 Step 1 的选择展示不同感受词（多选胶囊）：
   - 不好：没睡够、断断续续、老醒过来、入睡很难、醒来更累、做噩梦、睡不踏实、几乎没睡
   - 一般：还行、说不上来、不太稳、有点浅、醒来一般、中途醒过、够睡但不舒服
   - 好：睡得沉、醒来轻松、比较放松、很踏实、有精神一点、恢复了一点
2. 加"其他感受"自由输入。
3. 底部"下一步"按钮。

**Step 3：大概上床时间**
1. 标题"大概几点上床睡的？"，口语化范围选项：晚上8点前 / 晚上8点多 / 晚上9点多 / 晚上10点多 / 晚上11点多 / 凌晨0点多 / 凌晨1点多 / 凌晨2点以后 / 记不清。
2. 单选，选中后自动进入 Step 4。

**Step 4：大概入睡时间**
1. 标题"大概几点睡着的？"，根据 Step 3 的上床时间动态过滤选项（只显示上床时间及之后的选项）。
2. 额外加入"几乎没睡着"和"记不清"。
3. 单选，选中后自动进入 Step 5。

**Step 5：大概醒来或起床时间**
1. 标题"大概几点醒的？"，范围选项：早上6点前 / 早上6点多 / 早上7点多 / 早上8点多 / 早上9点多 / 上午10点多 / 上午11点以后 / 记不清。
2. 单选，选中后自动进入 Step 6。

**Step 6：夜里醒着大概多久**
1. 标题"夜里醒着大概多久？"，选项：基本没醒 / 醒过一下 / 半小时以内 / 半小时到一小时 / 一两个小时 / 很久 / 整晚没睡 / 记不清。
2. 单选，选中后自动进入 Step 7。

**Step 7：确认页**：汇总展示所有选择。

#### 底层逻辑规则

- 所有时间步骤使用口语化范围选项，每个选项含 label（用户看到）、rangeText（保存的标准范围文案）、estimate（估算值，如"22:30"）。
- 入睡时间动态过滤：根据上床时间的 hour 值，过滤只显示大于等于该 hour 的选项。
- "记不清"选项不生成估算值，不阻止保存。
- 同一天只保留一条睡眠记录，新记录覆盖旧记录。

#### 文案与措辞

- Step 1 标题：「昨晚睡得怎么样？」
- 整体感受：好 / 一般 / 不好
- Step 3 标题：「大概几点上床睡的？」
- Step 4 标题：「大概几点睡着的？」
- Step 5 标题：「大概几点醒的？」
- Step 6 标题：「夜里醒着大概多久？」
- 选项：基本没醒 / 醒过一下 / 半小时以内 / 半小时到一小时 / 一两个小时 / 很久 / 整晚没睡 / 记不清

### 4.7 活动记录（ActivityRecordWizard）

#### 完整交互流程

**Step 1：活动大类**
1. 标题"今天做了什么？"，8 个卡片选项：出门走走 / 学习/写作业 / 家务/整理 / 运动 / 洗漱/照顾自己 / 社交/和人接触 / 兴趣/放松 / 其他。
2. 单选，选中后自动进入 Step 2。

**Step 2：具体活动**
1. 根据 Step 1 大类显示具体活动细项（多选胶囊）：
   - 出门走走：楼下走了走、去了便利店、晒太阳、散步、通勤
   - 学习/写作业：上课、写作业、看书、复习、整理资料
   - 家务/整理：收拾桌面、洗衣服、倒垃圾、整理房间、洗碗

   - 其他：无预设细项，直接自由输入
2. 底部"下一步"按钮。

**Step 3：持续时间**
1. 标题"大概持续了多久？"，单选胶囊：不到 10 分钟 / 10-30 分钟 / 30-60 分钟 / 1 小时以上 / 记不清。
2. 选中后自动进入 Step 4。

**Step 4：做完后感受**
1. 标题"做完后感觉怎么样？"，多选胶囊：轻松了一点 / 还可以 / 有点累 / 很耗尽 / 有点烦 / 身体不舒服 / 没什么感觉。
2. 底部"下一步"按钮。

**Step 5：确认页**。

#### 文案与措辞

- Step 1 标题：「今天做了什么？」
- 活动大类：出门走走 / 学习/写作业 / 家务/整理 / 运动 / 洗漱/照顾自己 / 社交/和人接触 / 兴趣/放松 / 其他
- Step 3 标题：「大概持续了多久？」
- Step 4 标题：「做完后感觉怎么样？」

### 4.8 体重记录（WeightRecordWizard）

#### 完整交互流程

**Step 1：体重数值**
1. 标题"今天体重多少？"，数字键盘输入框 + 步进微调按钮（±0.1 kg）。
2. 默认值：上次体重记录值（无历史时为空，显示手动输入框）。
3. 输入后自动进入 Step 2。

**Step 2：测量场景**
1. 标题"什么时候称的？"，单选胶囊：起床后 / 饭前 / 饭后 / 晚上 / 随手称的 / 记不清。
2. 选中后自动进入 Step 3。

**Step 3：补充说明**
1. 标题"还有什么想补充的吗？"，两个选项：
   - "没有补充"（单选，自动进入确认页）
   - "写一点"（展开自由输入框）
2. 点击"没有补充"自动进入 Step 4。

**Step 4：确认页**：显示体重值、测量场景、补充说明。

#### 底层逻辑规则

- 体重值保存后作为下次默认值，持久化到 recordHistory。
- 初始 mock 历史值为 55.0 KG。
- 体重值必须为正数，否则不保存。
- BMI 解读在确认页根据身高计算（通过 calculateBMI），状态分为偏瘦（<18.5）/ 正常（18.5-25）/ 偏胖（25-30）/ 明显偏胖（≥30），但只在确认页展示参考信息，不做评价。

#### 文案与措辞

- Step 1 标题：「今天体重多少？」
- 单位：kg
- Step 2 标题：「什么时候称的？」
- 场景选项：起床后 / 饭前 / 饭后 / 晚上 / 随手称的 / 记不清
- Step 3 标题：「还有什么想补充的吗？」
- 选项：没有补充 / 写一点
- BMI 参考文案：「低于常用参考范围」/「在常用参考范围内」/「高于常用参考范围」/「明显高于常用参考范围」

### 4.9 记录确认页与返回机制

#### 底层逻辑规则

- 确认页有三种来源：
  1. 用户完成所有步骤后进入确认页（phase="confirm"）。
  2. 用户从确认页进入某一步修改（editMode=true），完成后直接回确认页。
  3. 确认页点击"完成记录"后原地切换为 success 态（phase="success"），不跳转独立页面。
- success 态显示盖章动画，底部按钮变为"回到记一下"。
- 点击"回到记一下"回到记录首页。

#### 返回确认机制

- 用户在 wizard 中途点击返回按钮：
  - 已保存（isRecordSaved=true）：直接返回首页。
  - 安全承接页激活：弹出安全退出确认（safetyExit）。
  - 有未保存内容（hasCompletedFirstStep=true）：弹出 moodExit 三选一浮层。
  - 无任何填写（hasAnyAnswer=false）：直接返回。

#### 文案与措辞

- 确认页标题：「这条记录已经完整了」
- 确认页按钮：「完成记录」/「先记到这儿」
- success 态按钮：「回到记一下」
- 返回确认浮层（moodExit）：
  - 标题：「这条记录还没有保存」
  - 说明：「你可以继续记录，也可以先把已经记下的内容保存起来。」
  - 按钮：「继续记录」（主） / 「保存当前内容」（次） / 「不保存退出」（弱）

## 五、回头看看（LookbackPage）

### 5.1 模块定位

回头看看是用户回顾过往记录的可视化工具，入口在更多菜单中。用户可查看近 7/14/30 天的情绪、睡眠、饮食、服药、活动、体重记录，按周或月切换时间粒度，查看趋势图表和每日详情，支持编辑和删除记录。

### 5.2 完整交互流程

1. 用户从更多菜单点击"回头看看"，进入页面。
2. 页面顶部：返回按钮 + 标题"回头看看"。
3. 时间模式切换：按周查看 / 按月查看（两个 tab 切换）。
4. 时间范围切换器：显示当前周范围（如"7.6 - 7.12"）或月份（如"2026年7月"），左右箭头切换上/下一周（月），不能超过当前时间。
5. 场景标签栏：情绪 / 入睡 / 三餐 / 服药 / 活动 / 体重，6 个标签横向排列，点击切换。
6. 主体区域：展示当前场景的每日数据，
   - 按周：7 天横轴，每日数据以卡片/图表形式展示。
   - 按月：当月每天数据网格。
7. 用户点击某一天，弹出详情抽屉（DetailSheet，底部浮层），展示该天该场景的完整记录。
8. 详情抽屉中：
   - 显示完整记录内容（情绪词、触发事件、身体感受、补充说明等）。
   - 操作按钮：编辑、删除。
   - 删除：将该日期对应场景字段置空，本地覆盖生效。
   - 编辑：进入编辑表单（EditSheet），修改后保存，回到详情抽屉。
9. 底部场景切换提示：显示当前场景名称，左右箭头切换场景。
10. 支持横滑手势切换时间（左滑下一周/月，右滑上一周/月）。

### 5.3 底层逻辑规则

- 数据源：`src/data/lookback.ts` 使用确定性 hash 生成 30 天 mock 数据，基于日期产稳定伪随机，避免刷新漂移。
- 7 天数据是 14 天的子集，14 天是 30 天的子集，保证切换范围时数据连续。
- 每日数据包含：情绪（分值和词）、睡眠（入睡/醒来/时长/夜醒）、三餐（早/午/晚状态 yes/no/unknown）、服药（早/晚状态 taken/missed/changed/unknown）、活动（0-3 级）、体重（kg）。
- 数据生成时各字段有缺失概率（如情绪约 12% 未记录、睡眠约 15% 未记录），模拟真实记录不完整场景。
- 场景分类 6 个：mood（情绪）/ sleep（入睡）/ meals（三餐）/ med（服药）/ activity（活动）/ weight（体重）。
- 每个场景有独立配色（CSS 变量），用于标签、趋势线、标记点。
- 删除/编辑通过本地 overrides 实现，不修改原始 mock 数据。
- 时间切换不能超过当前时间（未来周/月不可达）。

### 5.4 状态与边界情况

- 无记录日期：对应字段显示为空或"未记录"。
- 详情抽屉：叠加在底部，半屏浮层，点击遮罩或关闭按钮关闭。
- 编辑表单：编辑后回到详情抽屉并刷新数据。
- 删除后：该日期对应场景数据置空，toast 提示"已删除"。

### 5.5 文案与措辞

- 页面标题：「回头看看」
- 时间模式：按周查看 / 按月查看
- 场景标签：情绪 / 入睡 / 三餐 / 服药 / 活动 / 体重
- 周范围格式：「7.6 - 7.12」
- 月范围格式：「2026年7月」
- toast：已删除

### 5.6 视觉/交互细节

- 场景标签栏位于时间范围下方，横向排列。
- 切换场景和时间时使用横滑动效（spring 动画）。
- 详情抽屉从底部滑入，圆角顶部。
- 数据按日展示，每行不低于 52px。
- 情绪用月相图标（MoonPhaseIcon）表示 1-5 分值。
- 三餐状态用颜色标记（yes=绿色 / no=灰色 / unknown=浅灰）。
- 服药状态用颜色标记（taken=绿色 / missed=橙色 / changed=蓝色 / unknown=灰色）。
- 全局 toast 居中悬浮在底部，不跟随局部容器。

### 5.7 模块间关联

- 数据与记录流程的保存字段对齐（如情绪 moodWords、睡眠 sleepTime 等）。
- 场景分类颜色与记录流程各模块保持一致。
- 不直接读取记录流程的实时数据，使用 mock 生成器。

## 六、帮我整理（OrganizePage）

### 6.1 模块定位

"帮我整理"是用户在重要沟通（如与医生面诊）前，将记录的日常数据整理为沟通材料的工具。入口在更多菜单中。流程分两步：选择沟通对象 → 确认沟通重点（含高风险记录确认）。最终产出沟通清单（给用户自己看）和完整材料（给专业人士看）。

### 6.2 完整交互流程

#### 选择沟通对象（ContactStep）

1. 用户从更多菜单点击"帮我整理"进入。
2. 页面标题"帮我整理"，展示已添加的沟通对象列表（卡片形式）。
3. 初始 mock 沟通对象：王医生（精神科医生），来源为"本人添加"。
4. 用户点击已有沟通对象卡片，进入下一步（TopicsStep）。
5. 用户可点击"新增沟通对象"：
   - 展开底部浮层，选择角色（医生 / 家长或支持者 / 学校或老师 / 心理咨询师 / 其他）。
   - Demo 阶段仅"医生"角色可用，其余标记"暂未开放"。
   - 输入姓名，点击"确认"保存。
6. 也可从"可信联系人"中快速添加（Demo 阶段仅有"我爸爸"一个候选）。
7. 长按已有沟通对象可删除，弹出确认提示。

#### 确认沟通重点（TopicsStep）

1. 页面标题"和{name}的沟通"，进度条显示 1/2。
2. 副标题"这次想和{name}聊什么？"。
3. 时间范围信息卡片：显示当前选定日期范围（如"6月15日—7月17日"），以及"X 天中有 Y 天留下记录"。可点击"修改范围"按钮。
4. 修改时间范围弹出底部浮层，选项：最近 7 天 / 最近 14 天 / 最近 30 天 / 自定义时间。默认自定义时间（2026-06-15 至 2026-07-17）。
5. 沟通重点卡片列表（5 条 mock 默认全部选中）：
   - 每条卡片显示：标题、内容摘要、来源标签（系统整理/本人补充）、是否已编辑标记。
   - 点击卡片切换选中/取消，选中态：白底 + 绿色边框 + 绿色勾选框。
   - 展开"查看依据"显示该条沟通重点的原始记录依据。
   - 点击"修改"进入编辑面板（底部浮层），可修改标题和内容，保存后标记"已编辑"。
6. 底部"补充一条"按钮：用户可手动添加系统未整理出的内容，填写标题和具体说明，标记为"本人补充"。
7. 底部按钮："确认这 N 条"（N 为已选数量，未选时置灰）。
8. 点击确认后，如果有高风险记录，进入 DisclosureStep；否则直接进入 DoneStep。

#### 高风险记录确认（DisclosureStep）

1. 页面标题"和{name}的沟通"，进度条显示 2/2。
2. 副标题"高风险记录确认"。
3. 高风险记录卡片列表，每条卡片展示：
   - 来源：情绪记录 / 对话模式（橙色标签）
   - 时间（如"6月24日 01:32"）
   - 用户原话（完整展示，不改写、不摘要）
4. 默认全部不选。用户点击卡片切换选中/取消。
5. 底部两个按钮：
   - "都不放入"（点击后不纳入任何高风险记录，进入完成页）
   - "放入 X 条"（X=已勾选数量，为 0 时右侧置灰，点击后进入完成页）

#### 完成页（DoneStep）

1. 页面标题"和{name}的沟通"，右上角模块图标（返回整理首页）。
2. 副标题"和{name}沟通的内容已整理好"。
3. 沟通信息卡片：
   - {name} · {roleLabel}
   - 记录日期、记录天数（X/Y）
   - 沟通重点（编号列表）
   - 高风险记录（如有，显示"已加入 X 条"）
   - 创建日期
4. 主按钮：查看完整材料（进入 MaterialDetailView 全屏页）。
5. 两个次级按钮并排：
   - 分享给{name}（点击后先弹出确认对话框，确认后执行分享）
   - 保存材料（点击后先弹出确认对话框，确认后下载为 .txt 文件）

#### 导出确认对话框（MaterialExportConfirmDialog）

1. 分享/保存操作触发前，弹出底部浮层确认对话框。
2. 显示内容：
   - 操作类型（分享/保存）
   - 接收者（分享时显示对方姓名）
   - 高风险记录数量
   - 隐私后果提醒
3. 两个按钮：
   - "继续分享" / "继续保存"（主按钮）
   - "取消"（次按钮）
4. 点击取消、关闭浮层、按 Escape 键均不触发导出。

#### 沟通清单（CommunicationChecklistView）

1. 从完成页或其他入口查看沟通清单。
2. 简洁形式的沟通总结，给用户自己看，可快速扫读。
3. 不展示完整统计和所有记录细节。

## 九、能量系统（跨模块）

### 9.1 模块定位

能量系统是跨模块的数值激励系统，通过完成记录、轻社交、夸夸等行为获得能量。能量值在右上角统一展示，获得时触发粒子飞行动画。

### 9.2 底层逻辑规则

- 全局能量值存储在 `userProfile.energy` 中，通过 localStorage 持久化。
- `useEnergy` hook 使用 pub/sub 模式实现跨模块同步：
  - 初始化时从 localStorage 读取最新值。
  - 订阅 `subscribeEnergy`，任一模块调用 `addEnergy` 后即时刷新。
  - freeze/unfreeze：用于能量飞行动画期间冻结展示值，避免数字在 toast 抵达前跳变。
- 能量奖励来源：
  - 完整记录：+10 能量（`FULL_RECORD_ENERGY_REWARD`）
  - 创建夸夸卡片：+5 能量（`PRAISE_CARD_ENERGY_REWARD`）
  - 一起发呆：+3 能量
  - 一起吃饭：+3 能量
- 能量奖励幂等：同一记录/卡片不重复发放（通过记录 ID 去重）。
- 演示模式下不触发能量奖励。
- 点击能量入口显示提示："小装扮兑换暂未开放"（Demo 阶段）。

### 9.3 视觉/交互细节

- 能量入口（EnergyBadge）：全局统一样式
  - 图标：种子发芽图标（SproutIcon）+ 数字
  - 浅色圆角胶囊（rounded-full）
  - 定位模式：inline（参与标题栏布局）或 floating（absolute 右上角悬浮）
  - 点击反馈：紧贴下方展开轻提示，1.8 秒自动淡出
  - pulse 动画：能量飞抵后 scale 脉冲（420ms）
- 能量获得反馈（EnergyRewardFeedback）：
  - 粒子从页面中央飞向能量入口
  - 飞行期间冻结展示值
  - 到达后解冻 + 触发 pulse 动画
  - 显示文字如"获得 +10 能量"

### 9.4 模块间关联

- 所有模块通过 `useEnergy` hook 读取能量值。
- 记录流程、夸夸、轻社交模块触发能量奖励。
- 能量值在 userProfile 中与用户资料一同持久化。
